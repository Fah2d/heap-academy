## What and why

Part 1, built test first:

1. **Only courses and chapters with a published lesson** (`src/content/published.ts`; FR-CAT-04, FR-CRS-01). The publish guard refuses to publish a course with no published lesson, but its lessons can be moved back to draft after it. Such a course is now left out of the course list, and its page answers as no course. A chapter with no published lesson is not shown on the course page.
2. **A warm cache makes no database query** (`src/content/warm-cache.test.ts`; the "Done when" line of WP-5.1). The test replaces the framework's data cache with one that keeps each answer by its key and arguments, as the real one does. A second view of the course list or of a course page then makes no query, and a failed read is never kept, so the next view asks again. These tests passed on the existing wiring from WP-4.1 the first time they ran; they guard it from now on.
3. **The sitemap** (`src/app/sitemap.ts`, `src/features/catalog/server/sitemap.ts`; FR-SEO-01). `/sitemap.xml` lists `/`, `/courses` and each published course, at the production address. It is read per request from the cached content, because a sitemap made at build time would keep whatever the build could read. When the courses cannot be read it fails, so a crawler retries instead of reading a sitemap that has lost every course.
4. **The indexing rules** (`src/app/robots.ts`, `src/features/catalog/robots.ts`; FR-SEO-01). `/robots.txt` allows every page, closes `/api/`, and names the sitemap. Sign-in and the admin pages already say `robots: { index: false }` in their own metadata (WP-2.2, WP-2.3); a disallow line would stop a crawler from reading that, so they are not disallowed.
5. **Canonical addresses resolve against `https://heapacademy.dev`** (`src/features/catalog/site.ts`, `metadataBase` in `src/app/layout.tsx`). The pages in part 2 set their own canonical paths.

Part 2, built test first (commits 1fba0b1 and 7ac30d7):

When the read fails, an error notice says the courses could not be loaded.
8. **The course page** (`/courses/[course]`; FR-CRS-01). The home page has a whole title of its own; the course list is "Courses | Heap Academy"; a course page uses the course's title and its summary as the description. Each names its canonical path. A page whose content could not be read says `noindex`, so a crawler never keeps the failure as the page.

Each read first waits for the request (`connection()`): the first build of part 2 logged two failed content reads, because the build tries to prerender each page and the page starts rendering beside the root layout. ## Decisions taken with a safe default (please confirm or change)

1. **Base branch.** The work-package procedure says to stop when a dependency is unmerged. The owner's task list says to branch from `origin/wp/4.1-courses-chapters`, so the branch is `wp/5.1-catalog` from there.
2. **A course with no published lesson is not found, and an empty chapter is hidden.** FR-CAT-04 asks for the first in the list; the course page follows it so a link cannot reach a page with nothing to learn. A chapter with only drafts would show a heading over nothing, so it is left out until it has a published lesson.
3. **The production address is a constant, not a new environment variable.** `https://heapacademy.dev` is the owner's domain of 2026-11-21 (`docs/runbooks/infrastructure-setup.md`). A new required variable would need the owner to set it in Vercel and in CI before any build passes. Previews therefore name the production address as canonical, which also keeps them from presenting themselves as pages to index.
4. **`robots.txt` closes only `/api/`.** Pages left out of indexing use their own `noindex` metadata, which a crawler must be allowed to read.
5. **The sitemap fails when the courses cannot be read**, instead of answering with only `/` and `/courses`.
6. **The sitemap lists only pages that exist on this branch.** Lesson pages (`/learn/...`, WP-5.2) and `/privacy` and `/terms` (WP-6.3) join it when they are built.
7. **No link to a lesson and no Begin action on the course page until the workspace route exists** (WP-5.2), because a link to a page that does not exist is a dead control (CLAUDE.md rule 3). The progress and the state-matched action of FR-CAT-02 and FR-CRS-02, and each lesson's XP, are WP-5.4. Until then the course page has no primary action, which DESIGN.md section 2 expects on every page; it arrives with WP-5.2.
8. **The home page explains Run, Check and the visible test cases** before the lesson page exists on this branch. It describes the product as WP-5.2 builds it, beside this package. If WP-5.1 merges first, the paragraph describes a page a visitor cannot reach yet.
9. **A failed read is shown inside the page with status 200 and `noindex`**, instead of throwing to the error page. The states table in 03-experience section 8 names "Could not load" as a state of the course list and the course page. The home page and the course list keep their heading and say what failed; the course page, which has no title to show, has its own heading.
10. **The course title is a `standalone` link (weight 500) inside its heading**, so it keeps the 44 px target. DESIGN.md gives headings weight 600; the link primitive has no variant that is both. Changing the primitive is left to the design review.
11. **`aria-current="page"` only on `/courses` itself**, not on a course page, which is a different page. The header therefore marks nothing on a course page.
12. **The header wraps** (`flex-wrap`) rather than shrinking text, so the wordmark, Courses and Sign in never overflow at 320 px. Not yet seen in a browser.

13. **The journey waits out the content cache, up to 75 seconds.** Published content is cached for 60 seconds (`CONTENT_REVALIDATE_SECONDS`), and the first view after that still answers the old list while it refreshes. A course list read by an earlier test can therefore hide the new course. The journey reloads `/` and `/courses` until the course shows, for at most 75 seconds, instead of clearing the cache, which would need a route that only tests use. On a fresh server, as in CI, the first load shows it.
14. **The journey writes content straight into the database**, as `supabase/seed.sql` does: each lesson through `save_lesson` as validated, then published. Going through the dashboard would need an admin at `aal2` and WP-4.3's validation, which is not on this branch.
15. **`/admin/courses/new` is classified as not indexed.** It is not a row of its own in 03-experience section 3, but it is an admin page.
16. **The catalog gallery is a development-only page with sample content**, like `/dev/admin`. The sample titles are written in `src/messages/gallery.ts`, not shown to learners, and absent from the build.
