# WP-9.1 whole-application design review 1

Reviewer: `design-reviewer`, fresh context. It reviewed every screen recaptured at commit 5587e1f on `wp/9.1-visual-polish`. That covers WP-8.2's interface changes too. Verdict: CHANGES REQUIRED. There were no blockers, 4 majors and 13 minors.

| ID | Severity | Finding | Answer |
|---|---|---|---|
| M1 | MAJOR | With the on-screen keyboard open, the fixed bar covers the editor. The progress block wraps to two lines in a 192 px box. | The progress bar now spans the bar's width below 768 px, so "Starting Python" and the byte count sit on one line and the bar is one line shorter. The chrome above the editor is not collapsed: on a real phone the browser scrolls the caret's line into view, and the test cannot show that (its comment says so). **Not verified:** how much editor shows above a real keyboard on an iPhone and an Android phone. That is for the owner. |
| M2 | MAJOR | A revealed hint is lost when the layout crosses 768 px. | Fixed. The count lives in `Workspace`. Only a hint just asked for takes the focus; a rebuilt list leaves the focus where it was. A unit test reveals a hint, crosses 768 px, and checks the hint is still open and the focus did not move. It failed before the change. `workspace-a11y-runtime.spec.ts` now checks the open hint and runs axe at 1280, 768 and 375, and `workspace-hint-375.png` shows the open hint. |
| M3 | MAJOR | The phone views do not fill the screen. | Fixed. Below 768 px `main` is a column, and the views, the editor box and the output section take the height left. The fix found a defect that is also on `main`: the site footer lay under the fixed action bar, so its links were covered. The bar's height is now written on `<body>`, which pads its end by it, so the footer sits above the bar. At 375×740 the footer is at y 546 to 615 and the bar starts at 615. |
| M4 | MAJOR | Long expected and actual output lines are cut with no sign they continue. | Fixed. The test case blocks use `.scroll-visible`. That cue is real: with Playwright's `--hide-scrollbars` turned off, a lesson code block at 375 px shows an 8 px bar (`offsetHeight − clientHeight = 8`). See `screens/WP-9.1/manual-lesson-code-scrollbar-375.png`, a manual capture. The test screens cannot show it, because Playwright hides scrollbars in headless Chromium. **Not verified:** iOS and Android overlay scrollbars. |
| m1 | MINOR | The admin preview at 1280×720 is crowded, and its footer starts at x=16. | Fixed. The footer spans the window only beside the learner's lesson bar, so in the preview it lines up with the header at x=80. The preview's back link and title share one row. The frame drops its 32 px block padding around the preview from 1024 px. At 1280×720 the editor box grew from 112 px to 170 px. |
| m2 | MINOR | CodeMirror gutters are collapsed in full-page dashboard captures. | This is a capture artifact: CodeMirror measures its gutter once an editor is in view. A new capture saves the lesson editor's Code section on its own, scrolled into view (`WP-9.1/admin-lesson-editor-code-1280.png`). |
| m3 | MINOR | The gallery headers show states that cannot occur. | Fixed. The profile and sign-in gallery screens capture the main region, or the dialog, only. The real header's states have their own screens. |
| m4 | MINOR | Test case names wrap under the status. | Fixed. The status keeps its width and the name wraps in its own column. |
| m5 | MINOR | After too many tries, Sign in stays the enabled primary. | No change. The auth service gives no wait time for code tries, so there is no moment at which to enable the button again. Disabled, the learner could not try after waiting. The notice says what to do. |
| m6 | MINOR | At 768 px the panels move when Python is ready. | Fixed. From 768 to 1023 px Python's status has its own row, kept at 44 px while empty. |
| m7 | MINOR | The ⌘ key hint smudges; the Check hint's colour pair is not in DESIGN.md 4.3. | The ⌘ comes from the Menlo fallback. It is correct at 3× (checked) and shows only on Apple devices, all 2× or more; only the 1× capture smudges it. The pair (`#362B11` on `#D4A017`, 5.85:1 as measured by the reviewer) is for the owner to add to DESIGN.md 4.3. DESIGN.md is signed, so it is not edited here. |
| m8 | MINOR | The display name reads as metadata; the stats break differently by state. | Fixed. The name is `--text-lg` in the text colour. Below 768 px the numbers are two to a row in every state. |
| m9 | MINOR | The deleted dialog keeps its question and has no control. | Fixed. The title becomes "Account deleted", and a "Go to the home page" link is there in case sign-out stalls. A unit test failed before the change. The gallery's deleted state checks both. |
| m10 | MINOR | The server reference is set in Plex Sans. | Not a defect. In a browser, the reference's computed font is `plexMono` (`/dev/error`). Plex Mono's digits look like Sans at this size. |
| m11 | MINOR | The marked lesson row is indented further than the others. | Fixed. Unmarked rows start their content at `--marker-indent` (the 2 px marker plus 12 px), so the lesson numbers form one column. It is padding, not a transparent border, which forced-colors mode would draw on every row. |
| m12 | MINOR | Only a cut edge of the console shows below an error card. | The output pane scrolls there. It now has the same visible scrollbar as code blocks. |
| m13 | MINOR | "You can undo this straight after." is an idiom. The home-empty 768 screen was taken before the editor loaded. | Fixed. The learner's reset dialog and the gallery's both say "The Undo button brings it back." The catalog gallery waits for the home editor before it saves a home screen. |
