# WP-5.1 security review 1 (condensed)

Reviewer: security-reviewer, of af42bd5 (`origin/wp/4.1-courses-chapters..af42bd5`). Verdict: APPROVE, with the minors below. Every attack traced is blocked: drafts and solutions (public reads only through `src/content`, a client with no session, and row level security returns published rows only), cache poisoning (no session client or `next/headers` in `src/content`, enforced by lint and `public-client.test.ts`), the sitemap (only `publishedCourses()`, addresses from a constant origin, so a forged `Host` changes nothing), failed reads (thrown inside `unstable_cache`, never stored; failure pages `no-store` and `noindex`), the dev gallery (404 in the production build, strings only in server source maps), logs (route and outcome only), headers (CSP nonce, `frame-ancestors 'none'`, HSTS, `nosniff`, referrer and permissions policies on every route probed; no header, proxy, dependency or workflow file changed).

- MINOR 1 (T-14, T-25), `src/content/published.ts:178-182`: every well-formed made-up course address costs a database query and a cached `null`; a loop of 5000 addresses makes 5000 queries and cache writes against the free tier until WP-7.1's firewall rule. Fix: look the address up in the cached `publishedCourses()` list first and answer `null` without a query; test that an unknown address makes no call.
- MINOR 2 (rule 9, T-21), `src/features/catalog/reads-only-content.test.ts:27`: the test sees only static imports, so `await import("@/infrastructure/db/session-client")` in a catalog file passes it and lint. Fix: match `import("...")` too, or a lint rule that stops `features/catalog` importing `infrastructure/*` and `next/headers`; add a dynamic import case.
- MINOR 3 (FR-SEO-01), `src/app/indexing.test.ts:71`: only `page.tsx` is found, but `next.config.ts` also builds `ts`, `jsx` and `js` pages; a `page.ts` admin page would skip the indexing check, and a `src/app/dev/x/page.js` would ship. Fix: match `/^page\.(tsx|ts|jsx|js)$/`, the same list as `PAGE_EXTENSIONS`.
- MINOR 4 (T-21, test strength), `e2e/catalog-journey.spec.ts:60`, `:230-231`, `:261`: draft content is checked only as visible text, never in the raw HTML or the page data; the seeded solution `print("hello")` is not unique and there is no wrong answer to look for. Fix: unique tokens for the draft lesson, draft chapter, draft course, solution and a wrong answer; assert none is in the response text of `/`, `/courses`, the course page or `/sitemap.xml`. Optional here (a slice of WP-7.1's canary).
- Note (not security), `src/features/catalog/server/metadata.ts:21,31,38`: an outage serves the catalog as 200 with `noindex`, which a crawler may drop from the index; a 503 is safer for ranking. Decision 9, the owner's call.
- Note (hygiene), `src/features/catalog/index.ts:4`: the development-only `CatalogStateGallery` is exported from the feature's public index. Import it by its own path in the `.dev.tsx` page instead.
